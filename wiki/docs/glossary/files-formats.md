# Files & Formats

## A2L File — *ASAP2 Description File*

The backbone of ECU calibration. Describes every measurable/calibratable variable inside the ECU — where it lives in memory, its data type, units, and conversion formula.

- Generated by the ECU compiler (from AUTOSAR or handwritten C)
- Consumed by CANape, INCA, and other calibration tools
- Without a valid A2L, you can't read or write ECU internals via XCP
- Contains: MEASUREMENT (read-only), CHARACTERISTIC (writable), AXIS_PTS

## DBC File — *CAN Database File*

Defines all CAN messages and signals on a given network. The single source of truth for what's on the bus. Edited in CANdb++ and consumed by CANalyzer, CANoe, and CANape.

- Describes: message ID, cycle time, signals, bit position, scaling, value tables
- Required to decode raw CAN frames into human-readable values
- Extended by .sym (symbol files) for complex data types
- Always version-control your DBC — mismatch causes garbage data

## FIBEX / ARXML — *Network Description (FlexRay / AUTOSAR)*

FIBEX is the FlexRay network description file. ARXML is the AUTOSAR system description format. Both can define Ethernet (SOME/IP) and complex network topologies.

- ARXML used in multi-bus architectures: CAN + LIN + FlexRay + Ethernet
- Imported into CANoe's System Designer
- Contains PDU mappings, frame slots, cycle lengths
- AUTOSAR Adaptive uses ARXML extensively for service definitions

## HEX / S19 File — *Flash File (Intel HEX / Motorola S-Record)*

Binary ECU firmware in text-encoded format. Used for ECU flashing via UDS programming sessions or bootloaders.

- Intel HEX (.hex): used widely across toolchains
- Motorola S-Record (.s19, .srec): common in automotive ECUs
- Flashed via UDS service 0x34 (Request Download) + 0x36 (Transfer Data)
- CANoe's DiVa and vFlash handle automated flashing workflows

## LDF File — *LIN Description File*

Equivalent of a DBC but for LIN buses. Describes frames, signals, schedules, and node definitions for a LIN cluster.

- Contains node (master/slave) definitions
- Defines frame schedules and signal encoding
- Used in CANoe/CANalyzer with LIN hardware

## MDF / MF4 File — *Measurement Data Format*

Standard binary logging format for measurement data. Captures timestamped signal values during test runs.

- MDF4 (.mf4) is the current standard — replaces older .dat formats
- Produced by CANalyzer, CANoe, CANape, DIAdem
- Can hold millions of signal samples at microsecond precision
- Opened and post-processed in DIAdem or CANape's analysis mode

## PAR File — *Parameter File*

Stores ECU parameter values for measurement and calibration sessions. Loaded into CANape or similar tools to pre-configure which signals to measure and at what addresses.

- Contains signal names, addresses, data types, scaling
- Linked to an A2L file — PAR gives the values, A2L gives the descriptions
- Saved after calibration sessions to preserve tuned values
- Common extension: .par (CANape), can also be project-specific
